⚠️  重要提示：在运行 docker-run.sh 之前，必须确保 Docker Desktop 已启动！

════════════════════════════════════════════════════════════════════════

1️⃣  在 Windows 上启动 Docker Desktop
════════════════════════════════════════════════════════════════════════

方法 A: 使用开始菜单（推荐）
┌─────────────────────────────────────────────────────────────────┐
│ 1. 点击 Windows 开始菜单
│ 2. 搜索 "Docker Desktop"
│ 3. 点击打开应用
│ 4. 等待 Docker 图标显示在系统托盘（可能需要 30-60 秒）
│ 5. Docker 已就绪，可以运行脚本
└─────────────────────────────────────────────────────────────────┘

方法 B: 使用 PowerShell 命令
┌─────────────────────────────────────────────────────────────────┐
│ 打开 PowerShell（管理员模式），运行：
│ 
│ Start-Process "C:\Program Files\Docker\Docker\Docker.exe"
│ 
│ 等待 30-60 秒，Docker 图标会出现在系统托盘
└─────────────────────────────────────────────────────────────────┘

方法 C: 使用任务栏快捷方式
┌─────────────────────────────────────────────────────────────────┐
│ 1. 如果之前打开过 Docker Desktop，右键点击系统托盘
│ 2. 找到 Docker 图标
│ 3. 如果显示"启动"，点击启动
│ 4. 等待 Docker 完全加载（图标不再闪烁）
└─────────────────────────────────────────────────────────────────┘

验证 Docker 已启动：
  • 系统托盘中出现 Docker 鲸鱼图标 ✓
  • 图标不再闪烁或显示加载动画 ✓
  • 在命令行运行 docker ps 无错误 ✓

════════════════════════════════════════════════════════════════════════

2️⃣  运行一键启动脚本
════════════════════════════════════════════════════════════════════════

在项目目录打开 PowerShell 或 Git Bash，运行：

  bash docker-run.sh

脚本会：
✓ 检查 Docker 是否启动
✓ 构建所有容器
✓ 启动所有服务
✓ 等待服务就绪（约 2-5 分钟）
✓ 显示访问地址和常用命令

4️⃣  常用命令
════════════════════════════════════════════════════════════════════════

查看所有容器状态：
  docker compose ps

查看实时日志：
  docker compose logs -f              (所有服务)
  docker compose logs -f server       (只看后端)
  docker compose logs -f client       (只看前端)
  docker compose logs -f postgres     (只看数据库)

重启单个服务：
  docker compose restart server
  docker compose restart client
  docker compose restart postgres

停止所有服务（保留数据）：
  docker compose down

完全清理（删除所有数据）：
  docker compose down -v

重新启动脚本：
  bash docker-run.sh

5️⃣  故障排除
════════════════════════════════════════════════════════════════════════

问题 1: "Docker daemon is not running" 错误
───────────────────────────────────────────
解决方案：
1. 按照第 1 部分启动 Docker Desktop
2. 等待 30-60 秒让 Docker 完全启动
3. 重新运行 bash docker-run.sh

问题 2: 容器启动失败
───────────────────────────────────────────
查看具体日志：
  docker compose logs postgres   (查看数据库日志)
  docker compose logs server     (查看后端日志)
  docker compose logs client     (查看前端日志)

常见原因：
  • 磁盘空间不足 → 清理磁盘或删除旧镜像
  • 端口被占用 → 关闭占用端口的应用
  • 内存不足 → 关闭其他应用，增加 Docker 内存分配

问题 3: 应用启动缓慢
───────────────────────────────────────────
这是正常的！首次运行：
  • 下载 Docker 镜像 (100-500MB)
  • 编译后端代码 (Rust)
  • 构建前端应用 (Next.js)
  总耗时：3-10 分钟

跳过 docker compose down 和 docker-run.sh 之间的间隔

问题 4: 无法连接到数据库
───────────────────────────────────────────
检查：
  docker compose ps
  确保 allowance-postgres 状态为 "Up"

如果不是，查看日志：
  docker compose logs postgres

6️⃣  开发工作流
════════════════════════════════════════════════════════════════════════

1. 启动服务：
   bash docker-run.sh
   
2. 在另一个终端查看日志：
   docker compose logs -f
   
3. 修改代码（后端 Rust 或前端 TypeScript）
   
4. 自动重新加载：
   • 后端：cargo watch 自动重新编译
   • 前端：Next.js dev 自动重新构建
   
5. 在浏览器刷新查看更改：
   http://localhost:3030
   
6. 完成开发后停止：
   docker compose down

8️⃣  性能优化建议
════════════════════════════════════════════════════════════════════════

在 Windows 上优化 Docker 性能：

1. 增加 Docker 内存分配：
   • 打开 Docker Desktop 设置
   • 进入 "Resources" → "Memory"
   • 调整到至少 4GB (推荐 8GB)
   • 点击 "Apply & Restart"

2. 启用 WSL 2 后端（如果未启用）：
   • Settings → General → "Use the WSL 2 based engine"
   • 重启 Docker

3. 排除项目文件夹的扫描：
   • 设置中的 "Resources" → "File Sharing"
   • 确保项目路径在列表中
   • 这样可以加快构建速度

总结
════════════════════════════════════════════════════════════════════════

快速启动步骤：

  1. 启动 Docker Desktop（开始菜单或任务栏）
  2. 等待 30-60 秒直到 Docker 完全启动
  3. 打开项目文件夹，进入 PowerShell/Git Bash
  4. 运行：bash docker-run.sh
  5. 等待服务启动（2-5 分钟）
  6. 在浏览器打开：http://localhost:3030
  7. 完成！✅

有问题？查看日志：docker compose logs -f
